Photography doctrine

Real photography only. Mountain, landscape, interior, lifestyle. Client-supplied photos take precedence; Unsplash fallback only for slots the client did not supply.

Always

  • Real photography (mountain · landscape · interior · lifestyle)
  • Client-supplied photos first (from assets/)
  • Full-bleed in hero blocks (16:9 minimum)
  • Portrait aspect for headshots (3:4, 4:5, 5:6)
  • Gradient overlay over hero photos for text legibility
  • Subtle treatment filter: saturate(0.95) brightness(0.98)
  • Lazy load all below-the-fold images

Never

  • Stock illustrations, vectors, or 3D renders
  • Auto-inject Unsplash top search result per slug
  • Food, restaurant, farmers-market imagery
  • Landscape aspect on headshot blocks
  • Pure black/white (use warm-black #1f1c18 and warm-white #fbf9f5)
  • Photos requiring updates (avoid time-sensitive shots)

Copy doctrine (anti-AI-slop)

Christian's voice is approachable, conversational, confident, relationship-driven. Avoid the patterns that read AI-generated.

Voice anchors

  • "Elevate Your Lifestyle" tagline (CS verbatim)
  • "Mountain living dreams" (CS live snippet)
  • "Strategic, detail-oriented approach paired with clear, consistent communication"
  • "Boutique-level service with modern tools"
  • First-person, specific, geographic ("Buena Vista," "Chaffee County," "Central Colorado")
  • Lived-in details (water rights, well permits, build sites, drive times)

Banned patterns

  • Em dashes anywhere (HARD ban — use comma, period, colon, middle dot ·)
  • "Dream home" / "seamless experience" / "trusted partner" / "elevate your dreams"
  • Parallel triplets ("integrity, communication, results")
  • Stat-led hero subtitles ("Over X transactions in Y years")
  • State-level scope on community/listing pages ("Colorado Homes for Sale" — use "Buena Vista" or "Central Colorado" instead)
  • Fabricated testimonials, names, awards, or stats

Build doctrine for Jeff and Kane

When implementing in WordPress (Astra + UAGB), follow these conventions to avoid the regression patterns from prior builds.

Astra setup

  • Theme: Astra (free)
  • Layout: full-width-container
  • Body bg: #fbf9f5
  • 7-key page meta lock (see feedback_astra_width_regression_after_page_post)
  • Constrain `.uagb-container-inner-blocks-wrap` to 1280px + `.ast-container` to 100% (per feedback_astra_full_bleed_with_constrained_inner)

IDX (Showcase IDX)

  • Featured Listings page: hero + Showcase IDX search-results shortcode placeholder zone
  • 7 community IDX landing pages: hero + shortcode (community-filtered)
  • NO designed listing-card UI — Showcase renders the listings via widget
  • Custom skin via #sidx-main-container scope, banned layout props (aspect-ratio, position, display, padding)

Forms (Gravity Forms)

  • Universal contact form schema (per reference_universal_contact_form)
  • Home Value form: visitor address + contact → instant on-screen estimate + agent CMA follow-up
  • Notification: highrockyliving@gmail.com
  • Zapier → GHL CRM (existing AgenticPress integration)

SEO (Rank Math)

  • Per-page focus KW from Christian-Kelly-Rank-Math-Snippets.docx
  • Focus KW MUST appear in H1 + at least one H2
  • No "Exact" match redirects (per feedback_rank_math_redirect_loops — infinite loops)
  • Run validate_redirects.py before deploy + smoke_test.py after
